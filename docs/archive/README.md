# Archive

Material kept for the record. **Nothing here describes the current state of the project.**

If a document here and a document outside the archive disagree, the one outside is right.

| Directory | What is in it |
|---|---|
| [`source-definitions/`](source-definitions/) | Feature definitions written to drive the build, mostly delivered |
| `superseded/brand/` | The earlier brand set, replaced by the artwork in `docs/brand/` |

## Why they were kept rather than deleted

These documents are where the thinking happened. The code shows what was built; they show what
was asked for, and the difference between the two is often the most interesting part.

They are archived rather than published as documentation because they are **source material** —
written in the future tense, describing intentions, some of which changed. Read as current-state
documentation they would mislead, which is precisely the failure the documentation rules exist to
prevent.

## What was extracted from them

Current facts from these documents were extracted into `docs/architecture/`, `docs/features/`,
`docs/journeys/` and `docs/decisions/` on 2026-10-15. Where one of them records *why* something
was chosen, that reasoning is now in an ADR or a line in `docs/decisions.md`.
